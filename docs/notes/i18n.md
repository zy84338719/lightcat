# 面板多语言（i18n）

目前支持 **中文（默认）** 与 **English**，面板右上角一个按钮切换（图标旁边显示 `English` / `中文`）。

## 为什么要 i18n、怎么做

- **选择语言**：`?lang=xx`（点切换按钮时带上，并写进 cookie `acs_lang`，有效期一年）
  → cookie → `Accept-Language`（浏览器语言）→ 默认中文。
- **文案怎么取**：模板里写 `{{T "中文原文"}}`，Go 里写 `i18n.T(lang, "中文原文", args...)`，
  前端写 `t("中文原文")`（译文由服务端按当前语言注入到 `window.I18N`）。

**为什么用中文字面量当 key**（而不是 `overview.title` 这种键名）：

1. 模板替换可以脚本机械化完成，不用给几百句话现起名字，也不会出现「键名和内容对不上」；
2. 同一条文案在模板、JS、后端天然共用一条翻译；
3. 漏翻一眼可见 —— 英文页面里还出现中文就说明漏了，验收里有断言卡这条。

代价：**改中文文案 = 改 key**，必须同步 `internal/i18n/strings_en.go`，否则英文会静默回落成中文。
所以有一道测试防线（`TestAllTemplateTextsTranslated`）：它会扫一遍模板与 `app.js` 里用到的
每个 key，少一条就报错。

## 模板的多语言实现

`Register` 时给**每种语言各解析一套模板**（`tpls map[string]*template.Template`），
语言在解析期就绑进 `T` 这个 FuncMap 函数里。这样：

- 模板里写法干净（就是 `{{T "..."}}`），每次渲染不用再做一次查表；
- 渲染时按请求语言挑一套即可（`renderLang`）。

计数类的文案要**整句带参数**（`{{T "共 %d 台" .Total}}`），不要用「词片段拼句子」
（`{{T "共"}} {{.Total}} {{T "台"}}`）—— 后者英文语序会错（把设备数说成 clients）。
这是第一版踩到的坑，已经在验收截图里发现并改掉了。

## 怎么加一种语言

1. 在 `internal/i18n/i18n.go` 的 `Langs` / `LangNames` 里加代码（如 `ja`）与自称（`日本語`）；
2. 新建 `internal/i18n/strings_ja.go`，`init()` 里 `Register(map[string]string{...})`；
3. `Normalize` 里加上该语言的识别（`ja` / `ja-JP` 之类）；
4. 跑 `go test ./internal/i18n/ ./internal/web/`：缺的文案会被测试逐条列出来。

## 验收

- 单测：`internal/i18n`（语言协商、译文查找、缺译文回落中文）、`internal/web` 的
  `TestAllTemplateTextsTranslated`（不漏翻）、`TestEnglishPagesHaveNoChinese`（英文页面无中文残留）、
  `TestLanguageNegotiation`（`?lang=` / cookie / `Accept-Language` 优先级）、`TestLoginPageEnglish`。
- `verify-s1.sh` 第 37b 节：默认中文、`?lang=en` 英文、切语言写 cookie、带 cookie 保持英文、
  `?lang=zh` 切回中文、**英文页面里没有中文残留**。
- 另做了一次「中文零回归」比对：改动前后抓同一批页面（列表/详情/无线编辑/设置/接口），
  归一化掉新增的语言切换链接与 `window.I18N` 之后**逐字节一致**，只剩时间戳这类动态值。
  做这种几百处机械替换时，这道比对最值钱。

## 后端拼出来的字符串：显示时翻译

前端模板能写 `{{T "..."}}`，但**后端拼出来的字符串**（动作后的提示语、任务结果、终端分组名、
无线字段名）没法在 Go 里查表 —— `internal/web` 和 `internal/cwmp` 不该知道浏览器选了哪国语言。
处理办法：**存/传的仍是中文原文，显示时才翻译**（模板里用 `{{TS ...}}`）。

`i18n.TSmart` 分三层，逐层放宽：

1. **精确查表**：`"设置成功" → "Set successfully"`；
2. **占位符整串匹配**：把中文 key 里的 `%d/%s` 当捕获组（`"已采集 %d 个参数"`），
   命中后把值套进译文；
3. **逐段替换**：后端常把好几段拼成一句（`"信号 100%（4/4 格） · RSSI -41 dBm"`、
   `"设备上报：repeater · 上行 DHCP"`），整串匹配不上就**每一轮挑当前最长的那个匹配**替换，
   直到没有可替换的为止 —— 挑最长是为了不让「信号 %s」这类短 key 先把长串咬掉一截。
   捕获到的片段还会递归再翻一层（`"在线 1 小时 0 分"` 里的时长）。

认不出来就原样返回：宁可显示中文，也不要显示错的东西。

已知还会保持中文的两处（都是低频细节，不影响主流程）：

- FTTR 组网提示里拼进去的信号片段（`"设备上报：... · 信号 55%"` 里的「信号」两个字，
  因为 `信号 %s` 这个 key 太泛、会误伤 `信号 100%（4/4 格）`，所以没收录）；
- 提示语里内嵌的 Go 错误文本（`"保存失败：%s"` 的 `%s` 可能是 `listen tcp: ...` 这类系统错误，
  本身也不该翻译）。

## 仍保持中文的边角

模板、前端脚本与**设置页的提交反馈**都已双语（设置页把中文原文塞进 `?msg=`，模板用
`{{TS .Notice}}` 翻；`internal/i18n/strings_en.go` 末尾那组就是它的词条 —— 2026-10-12 补的，
此前英文界面下改端口 / 改密码 / 设 token 全会露出中文，而这几个恰是管理员最常做的动作）。

剩下的是**无线 / FTTR / 终端弹窗里由 Go 拼的分组名与提示**
（`internal/web/clients.go`、`fttr.go`、`wifi.go` 里拼好，模板侧用 `{{TS .K}}` 之类翻）。

它们走的是同一条 `TS` 兜底路径，**能翻大部分**，漏的是下面两类：

- 任务类型与任务结果（`internal/cwmp` 生成、存库后由面板显示）—— 这类要按「显示时查译文」
  处理，库里存的仍是中文原文，属于历史数据可读的折中；
- 嵌套括号拼出来的句子（见下）。

> 补这类文案有两个坑，都得用 `TSmart` 实跑才看得出来，光看词条表是查不出的：
>
> 1. **带动态尾巴的**（`"保存失败：" + err`）必须写成带 `%s` 占位符的词条，否则整串
>    匹配查不到（catalog 里没有那个完整串），静默回落成中文；
> 2. **嵌套括号的**（`无线组网（信号 75%（3/4 格））`）翻不干净 —— 外层翻了、里头的
>    「/4 格」留着。根因是占位符编译成非贪婪捕获 `(.+?)` 且带后续字面量锚定，
>    在嵌套括号处提前闭合；而译文里又保留了中文括号，逐段替换那层也接不上。
>    试过在 `tsmart` 里加兜底，结果兜底会被同一条词条的宽松正则再匹配回去、
>    形成死循环 —— 是该机制自身的固有局限，`tsmart` 保持原样，需要的话得换匹配策略
>    （比如按括号配平切段），那是独立一件事。
